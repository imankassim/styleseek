# EXP44 — Ranker with behavioural features

- **Role:** Context experiment (architecture §14)
- **Status:** Rejected before running — no genuine data to build it from
- **Run:** N/A

## Why this wasn't run

This experiment would add click/impression-derived features (e.g. historical click-through
rate) to the learning-to-rank model. The `event` table (Stage 7) does have impression/click
rows — but every single one of them was generated by this project's own automated browser
testing (Playwright smoke tests) and the author's manual clicks while building the UI, not by
genuine shoppers exploring the catalogue.

Architecture §9 training controls are explicit: *"Clearly label any synthetic behavioural
data"* and §16 names *"too little genuine interaction data"* as a named risk whose mitigation is
*"use human judgments and session features first... retain advanced models as experiments"*.
Building behavioural features from test-harness clicks would launder synthetic data as if it
were a real relevance signal — exactly what those two rules exist to prevent. There's also no
population of clicks large enough to compute a meaningful CTR from regardless of provenance.

## Decision

Rejected without running, same treatment as EXP21 (no description field to embed). Revisit only
once the site has genuine shopper traffic to draw features from — this is a "not yet", not a
"no".
